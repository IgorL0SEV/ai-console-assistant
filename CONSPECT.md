# Конспект: AI API и консольный ассистент

Заметки по теме — своими словами и с привязкой к тому, что сделано в коде.

## 1. AI API — это обмен сообщениями

Программа отправляет сервису список сообщений и название модели, получает
сгенерированный текст. Никакой «магии»: по сети идёт JSON, в котором есть
роль, содержимое и параметры запроса. Ответ тоже JSON — с текстом, причиной
остановки и расходом токенов.

## 2. Роли сообщений

- `system` — правила поведения и стиль. В нашем коде это отдельная строка
  `system` в запросе Anthropic и первое сообщение с ролью `system` в
  OpenAI-совместимом формате.
- `user` — реплика человека.
- `assistant` — ответ модели.

История собирается из пар `user` / `assistant`. Системный промпт не входит
в историю: он передаётся отдельно при каждом запросе.

## 3. Контекст хранит программа

API не помнит прошлые обращения. Если отправить только новую реплику, модель
ответит без учёта разговора. Поэтому `conversation.py` хранит список
сообщений, обрезает его до разумного размера и отправляет целиком.

Обрезка идёт парами: нельзя оставить ответ без вопроса. Поэтому лимит
приводится к чётному числу, а первое сообщение должно быть от пользователя.

## 4. Агрегатор моделей

ProxyAPI даёт один ключ и один базовый адрес к моделям разных компаний:
OpenAI, Anthropic, DeepSeek и другим. Это удобно, когда у провайдеров разные
биллинг и ограничения.

- OpenAI-совместимый путь: `https://api.proxyapi.ru/v1`, SDK `openai`.
- Anthropic Messages: `https://api.proxyapi.ru`, SDK `anthropic` сам
  добавляет `/v1/messages`.
- Ключ один, начинается с `sk-`, оплата в рублях.

Идентификатор модели включает вендора: `openai/gpt-5-mini`,
`anthropic/claude-sonnet-4-5`. На некоторых путях короткое имя подставляется
по умолчанию, но надёжнее указывать полное.

## 5. Два формата запроса

**Chat Completions (OpenAI).** Сообщения — список объектов `role` /
`content`; системный промпт — первое сообщение. Параметр длины —
`max_tokens` или `max_completion_tokens` в зависимости от модели.

**Messages (Anthropic).** Системный промпт — отдельное поле `system`,
`max_tokens` обязателен, ответ — массив блоков `content`. Блоки бывают
`text` и `thinking`.

Оба формата скрыты за общим интерфейсом `Provider.complete()`: CLI не знает,
какой SDK работает под капотом.

## 6. Reasoning

Рассуждающая модель тратит часть токенов на разбор задачи до ответа.

- В Anthropic это `thinking={"type": "enabled", "budget_tokens": 1500}`;
  модель возвращает блок `thinking` с ходом мыслей.
- В OpenAI-совместимом API это `reasoning_effort`; ход мыслей обычно скрыт,
  виден только итог.
- В OpenRouter используется объект `reasoning` с уровнем усилий.

Бюджет reasoning — компромисс: маленький обрывает размышления, большой
увеличивает задержку и стоимость. В проекте по умолчанию 1500 токенов,
`MAX_TOKENS` больше бюджета.

## 7. Токены и стоимость

Токены — единица тарификации. В ответе приходит `usage`: сколько токенов
ушло на вход и выход. Размышления тарифицируются как выходные, поэтому
думающая модель может стоить заметно дороже при коротком ответе.

В `ui.py` показываются вход, выход, reasoning и время ответа. В лог пишутся
только числа и модель, без текста диалога.

## 8. Ключи и .env

Ключ — секрет. Он лежит в `.env`, файл исключён из git. В репозитории есть
только `.env.example` с плейсхолдерами. Код читает ключ через
`python-dotenv`.

В логах и сообщениях об ошибках ключ маскируется: `errors.scrub()` заменяет
строки вида `sk-...` на `sk-***`.

## 9. Ошибки

- `401` — ключ не принят;
- `402` — недостаточно средств;
- `403` — доступ запрещён;
- `404` — модель не найдена;
- `429` — превышен лимит;
- `5xx` — временная ошибка сервиса;
- таймаут и сетевая ошибка — проблема связи.

Пользователь видит короткое объяснение, а не стектрейс. Технический текст
обрезается и очищается от ключей.

## 10. Режимы и переключение

Режим — это не отдельная программа, а выбор модели и параметров запроса.
`/normal` и `/thinking` пересоздают провайдера с другой моделью, история при
этом остаётся общей. Поэтому можно задать вопрос обычной моделью, а затем
попросить думающую разобрать ответ.

## 11. Ветки-пресеты

Один код — несколько профилей. Ветка задаёт провайдера по умолчанию, ключ,
модели и адреса. Это позволяет «дёрнуть» нужную LLM без переписывания CLI:

- `proxyapi` — агрегатор, основной вариант;
- `anthropic` — прямой Claude;
- `openai` — прямой OpenAI;
- `openrouter` — OpenRouter.

## 12. Проверка без сети

Тесты подменяют SDK-клиенты фейками: проверяются форма запроса, разбор
ответа, извлечение reasoning, ошибки и обрезка истории. `--demo` показывает
интерфейс без ключа. `--check` проверяет ключ и список моделей, не тратя
токены.

## 13. Главные выводы

- Контекст хранит клиент, а не модель.
- Формат запроса зависит от провайдера; общий интерфейс скрывает разницу.
- Reasoning — дополнительная возможность, а не гарантия одинакового
  поведения.
- Ключ — только в `.env`; в логах и скриншотах его быть не должно.
- Стоимость растёт с длиной контекста и бюджетом размышлений.
